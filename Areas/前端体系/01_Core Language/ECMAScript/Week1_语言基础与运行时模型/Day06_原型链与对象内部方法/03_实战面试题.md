# 原型链与对象内部方法 - 实战面试题

## 1. 经典对比：对象创建的 3 种方式

在面试中经常会对比字面量/构造函数/Object.create 的微小差异。

| 创建方式 | 代码示例 | 原型指向 (`__proto__`) | 性能与用途 |
| :--- | :--- | :--- | :--- |
| **对象字面量** | `const obj = { a: 1 }` | `Object.prototype` | 最常用，引擎优化最好，隐藏类创建极快。 |
| **构造函数/Class** | `const obj = new Foo()` | `Foo.prototype` | 用于批量生成具有相同结构和原型方法的实例。 |
| **Object.create()** | `const obj = Object.create(proto)` | 指定的 `proto` 或 `null` | 精确控制原型链，常用于继承或创建纯净字典。 |

## 2. 真实工程陷阱分析

### 陷阱 1：全局原型污染 (Prototype Pollution)
**场景**：很多第三方库提供深度合并 (deepMerge) 功能，如果未加校验直接合并来自 JSON 的恶意输入，会导致严重安全事故。
```javascript
const maliciousPayload = JSON.parse('{"__proto__": {"isAdmin": true}}');
const targetObj = {};

// 如果 deepMerge 实现有漏洞，会将其合并到了全局 Object.prototype 上
deepMerge(targetObj, maliciousPayload);

const randomUser = {};
console.log(randomUser.isAdmin); // true !! (系统被攻破)
```
**防御**：在深度拷贝/合并工具函数中，必须黑名单拦截 `__proto__` 和 `constructor` 键，或使用 `Object.create(null)` 作为容器。

### 陷阱 2：修改内置对象原型的蝴蝶效应
**场景**：给 `Array.prototype` 增加一个有用的工具方法。
```javascript
Array.prototype.myCustomUtil = function() { ... }
```
**问题**：由于默认 `defineProperty` 的 `enumerable` 是 true（如果直接赋值的话），这会导致所有使用 `for...in` 遍历数组的地方，都会意外地将 `myCustomUtil` 这个字符串作为键遍历出来！
**规避**：如果必须要扩展（通常极度不推荐），必须使用 `Object.defineProperty` 将其设为不可枚举 (`enumerable: false`)。

## 3. 核心手写题

### 3.1 手写：`instanceof` 运算符底层实现

**题目要求**：
实现一个函数 `myInstanceof(left, right)`，模拟 `left instanceof right` 的行为。需要深入理解原型链沿途查找的机制。

**完整答案**：
```javascript
function myInstanceof(left, right) {
    // 基础类型直接返回 false (instanceof 只能用于对象)
    if (left === null || (typeof left !== 'object' && typeof left !== 'function')) {
        return false;
    }
    
    // 构造函数必须有 prototype
    if (typeof right !== 'function') {
        throw new TypeError("Right-hand side of 'instanceof' is not callable");
    }

    // 获取目标原型
    const targetProto = right.prototype;
    
    // 获取实例的原型
    let currentProto = Object.getPrototypeOf(left);

    // 顺着原型链向上遍历，直到到达顶部的 null
    while (currentProto !== null) {
        if (currentProto === targetProto) {
            return true;
        }
        currentProto = Object.getPrototypeOf(currentProto);
    }
    
    return false;
}

// 测试
function Person() {}
const p = new Person();
console.log(myInstanceof(p, Person)); // true
console.log(myInstanceof(p, Object)); // true
console.log(myInstanceof([], Person)); // false
```

### 3.2 手写：模拟 `Object.create`

**题目要求**：
实现一个简易版的 `Object.create`，要求实现继承指定的原型。兼容不支持该原生的老旧环境。

**完整答案**：
```javascript
function myCreate(proto) {
    if (typeof proto !== 'object' && typeof proto !== 'function') {
        throw new TypeError('Object prototype may only be an Object or null');
    }
    
    // 技巧：利用一个空函数作为跳板
    function F() {}
    // 将空函数的原型指向目标原型
    F.prototype = proto;
    
    // new 该函数，返回的实例其 __proto__ 就自然指向了 proto
    return new F();
}
// 注意：老版浏览器用这种跳板法无法完美实现 Object.create(null)，因为 new 出来的对象依然有继承某些东西的风险。完美实现必须依赖现代 API。
```

### 3.3 手写：深度冻结 (Deep Freeze)

**题目要求**：
`Object.freeze` 只能冻结对象的第一层属性，实现一个 `deepFreeze` 递归冻结对象的所有层级。

**完整答案**：
```javascript
function deepFreeze(obj) {
    // 获取对象的所有自有属性名称
    const propNames = Object.getOwnPropertyNames(obj);

    // 遍历并在冻结自己之前先冻结内部引用的对象
    for (const name of propNames) {
        const prop = obj[name];
        
        // 如果属性值是对象，且未被冻结，递归调用
        if (prop !== null && typeof prop === 'object' && !Object.isFrozen(prop)) {
            deepFreeze(prop);
        }
    }

    // 将自己冻结 (防止新增、删除、修改、配置)
    return Object.freeze(obj);
}

// 测试
const user = {
    info: {
        age: 20
    }
};
deepFreeze(user);
user.info.age = 30; // 严格模式下报错，非严格模式下静默失败
console.log(user.info.age); // 20
```
