# 原型链与对象内部方法 - 使用维度

JavaScript 的面向对象体系是基于**原型 (Prototype)** 的。深入理解原型链机制以及对象属性的特性（Property Descriptors），是编写优雅且可维护的高级 JavaScript 代码的前提。

## 1. `__proto__` vs `Object.getPrototypeOf` 完整对比

在 JavaScript 中，获取和设置对象的原型有历史遗留的属性方案，也有现代标准的 API 方案。

| 特性 | `__proto__` | `Object.getPrototypeOf` / `setPrototypeOf` |
| :--- | :--- | :--- |
| **标准状态** | ES6 标准化为**附录B (历史遗留/浏览器专有)**，不推荐使用。 | **标准 API**，强烈推荐的官方方法。 |
| **存在位置** | `Object.prototype` 上的访问器属性 (getter/setter)。 | `Object` 构造函数的静态方法。 |
| **对纯对象(null原型)支持**| 失效。如果对象用 `Object.create(null)` 创建，它没有 `__proto__` 属性。 | **完美支持**。能够正确返回 `null`，也能对其设置原型。 |
| **性能** | 动态修改原型严重破坏引擎(如V8)的隐藏类机制，极其损耗性能。 | 同样损耗性能，修改原型的操作无论用哪种都应该避免。 |

> [!TIP]
> 永远使用 `Object.getPrototypeOf(obj)` 来读取原型。如果非要动态改变原型，使用 `Object.setPrototypeOf(obj, proto)`，但最好的实践是在对象**创建时**（如使用 `Object.create`）就将原型指定好。

## 2. 4 种继承模式演进 (附完整代码)

理解继承模式的演进有助于深入掌握原型链的运作。

### 模式 1：原型链继承 (老旧缺陷版)
直接把父类实例挂载到子类原型上。
**缺陷**：所有子类实例共享同一个引用类型的父类属性；无法向父类构造函数传参。
```javascript
function Parent() { this.colors = ['red']; }
function Child() {}
Child.prototype = new Parent(); // 核心

const c1 = new Child();
c1.colors.push('blue');
const c2 = new Child();
console.log(c2.colors); // ["red", "blue"] - 污染了其他实例！
```

### 模式 2：借用构造函数继承 (解决共享污染)
**缺陷**：无法继承父类原型链上的方法。
```javascript
function Parent(name) { 
    this.name = name; 
    this.colors = ['red']; 
}
Parent.prototype.sayHi = function() { console.log("Hi"); }

function Child(name, age) {
    Parent.call(this, name); // 核心：在子类实例上下文中执行父类构造函数
    this.age = age;
}
const c1 = new Child("Jack", 20);
// c1.sayHi(); // TypeError: c1.sayHi is not a function
```

### 模式 3：组合继承 (常用经典模式)
结合了上述两者的优点。
**缺陷**：父类构造函数被调用了两次（一次设置原型，一次在内部 call），导致子类原型上挂载了冗余的父类实例属性。
```javascript
function Parent(name) { this.name = name; }
Parent.prototype.sayHi = function() { console.log(this.name); }

function Child(name, age) {
    Parent.call(this, name); // 第二次调用
    this.age = age;
}
Child.prototype = new Parent(); // 第一次调用
Child.prototype.constructor = Child; // 修复构造函数指向
```

### 模式 4：寄生组合式继承 (完美的 ES5 方案)
直接将父类原型连接到子类原型，避免二次调用，**这是 ES6 `class extends` 的底层等价写法**。
```javascript
function Parent(name) { this.name = name; }
Parent.prototype.sayHi = function() { console.log(this.name); }

function Child(name, age) {
    Parent.call(this, name); 
    this.age = age;
}
// 核心：使用 Object.create 桥接原型链，而不实例化 Parent
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
```

## 3. instanceof 算法解释与实践

`instanceof` 运算符用于检测构造函数的 `prototype` 属性是否出现在某个实例对象的**原型链**上。

```javascript
function A() {}
const a = new A();
console.log(a instanceof A); // true
console.log(a instanceof Object); // true
```
**底层逻辑**：
不断提取实例 `a` 的原型 (`__proto__` / `getPrototypeOf`)，去和 `A.prototype` 进行引用比较，直到找到相等返回 `true`，或者直到原型链尽头 `null` 返回 `false`。

## 4. Object.create(null) 用例

在构建诸如事件总线 (Event Bus)、缓存池或纯数据字典时，我们往往需要一个非常纯净的哈希表 (Hash Map)。
普通的 `{}` 继承自 `Object.prototype`，存在 `toString`, `hasOwnProperty` 等内置方法，存在原型污染的可能。

```javascript
const map = Object.create(null);
map.name = "pure object";

console.log(map.toString); // undefined
console.log(map.__proto__); // undefined
```
> [!NOTE]
> `Object.create(null)` 创建的对象没有任何原型链开销，是纯粹的键值对容器。但在 ES6 后，更推荐使用原生的 `Map` 数据结构来处理此类需求。

## 5. 属性描述符 (Property Descriptors)

JavaScript 的属性不仅有键和值，每个属性还有一个包含其元数据的描述符对象。通过 `Object.getOwnPropertyDescriptor` 和 `Object.defineProperty` 操作。

属性分为两种：**数据描述符 (Data Descriptor)** 和 **访问器描述符 (Accessor Descriptor)**。

| 字段 | 说明 | 默认值 (defineProperty) | 默认值 (字面量创建) |
| :--- | :--- | :--- | :--- |
| `value` | 属性的值 (数据描述符独有) | `undefined` | 赋予的值 |
| `writable` | 是否可被赋值修改 | `false` | `true` |
| `get` / `set` | getter/setter 函数 (访问器描述符独有) | `undefined` | 无 |
| `enumerable`| 是否可通过 `for...in` 或 `Object.keys` 遍历 | `false` | `true` |
| `configurable`| 是否可以删除该属性，或者修改描述符 (一旦设为false，就无法再改回true) | `false` | `true` |

## 6. Object.freeze vs seal vs preventExtensions

这些方法用于在对象级别锁定变更，常用于安全防护和常量配置。

| 方法 | 新增属性 | 修改现有属性值 | 删除属性 | 修改描述符(配置) |
| :--- | :--- | :--- | :--- | :--- |
| `Object.preventExtensions(obj)` | ❌ 阻止 | ✅ 允许 | ✅ 允许 | ✅ 允许 |
| `Object.seal(obj)` (密封) | ❌ 阻止 | ✅ 允许 | ❌ 阻止 | ❌ 阻止 |
| `Object.freeze(obj)` (冻结) | ❌ 阻止 | ❌ 阻止 | ❌ 阻止 | ❌ 阻止 |

**注意**：这三个方法都是**浅操作 (Shallow)**。如果被冻结的对象属性是一个对象引用，内部对象依然可被修改。需要手动递归实现 `deepFreeze`。
