# 原型链与对象内部方法 - 底层分析

在 ECMAScript 规范中，对象不仅仅是属性的集合。真正定义一个对象行为的是它所实现的一系列**内部方法 (Internal Methods)**。

## 1. 13个必要内部方法 (Essential Internal Methods) 全列表

规范 Clause 6.1.7.2 规定了所有 ECMAScript 对象（无论是普通对象、数组还是 Proxy）都**必须**实现以下 13 个基本内部方法。这被称为对象的**多态接口**。

| 内部方法 | 签名 | 对应上层操作 (说明) |
| :--- | :--- | :--- |
| `[[GetPrototypeOf]]` | `() → Object \| Null` | `Object.getPrototypeOf(obj)`，获取原型。 |
| `[[SetPrototypeOf]]` | `(Object \| Null) → Boolean` | `Object.setPrototypeOf(obj, proto)`。 |
| `[[IsExtensible]]` | `() → Boolean` | `Object.isExtensible(obj)`。 |
| `[[PreventExtensions]]`| `() → Boolean` | `Object.preventExtensions(obj)`。 |
| `[[GetOwnProperty]]` | `(propertyKey) → Descriptor \| Undefined`| `Object.getOwnPropertyDescriptor(obj, key)`，忽略原型链查询。 |
| `[[DefineOwnProperty]]`| `(propertyKey, Descriptor) → Boolean` | `Object.defineProperty(obj, key, desc)`。 |
| `[[HasProperty]]` | `(propertyKey) → Boolean` | `key in obj`，**会沿原型链查找**。 |
| `[[Get]]` | `(propertyKey, Receiver) → any` | `obj[key]`，**会沿原型链查找属性值**。 |
| `[[Set]]` | `(propertyKey, value, Receiver) → Boolean` | `obj[key] = value`，设值时会触发诸多检测。 |
| `[[Delete]]` | `(propertyKey) → Boolean` | `delete obj[key]`。 |
| `[[OwnPropertyKeys]]` | `() → List of propertyKey` | `Reflect.ownKeys(obj)`，返回所有自有属性键。 |

*(另外，函数对象还有额外的 `[[Call]]` 和 `[[Construct]]` 方法，将在下一章详述。)*

> [!IMPORTANT]
> ES6 引入的 `Reflect` API 实际上就是将这 13 个引擎底层 C++ 实现的内部方法，原封不动地暴露给了 JavaScript 的应用层。

## 2. `[[Get]]` 属性查找：OrdinaryGet 递归算法

当我们执行 `console.log(obj.key)` 时，引擎底层执行了 `[[Get]](key, Receiver)`。
其核心算法 `OrdinaryGet(O, P, Receiver)` 流程如下：

1. 调用 `O.[[GetOwnProperty]](P)` 检查对象 `O` 本身是否拥有属性 `P`。
2. **如果没有找到：**
   a. 取出 `O.[[GetPrototypeOf]]()` 获取原型 `parent`。
   b. 如果 `parent` 是 `null`，返回 `undefined`。
   c. 递归调用 `parent.[[Get]](P, Receiver)`。
3. **如果找到了描述符 (desc)：**
   a. 如果它是**数据描述符**，直接返回 `desc.[[Value]]`。
   b. 如果它是**访问器描述符**，取出 getter 函数，如果在 getter 不存在则返回 `undefined`。否则使用 `Receiver` 作为 `this` 上下文去 `Call` 这个 getter 并返回结果。

**Receiver 的秘密：**
`Receiver` 代表了最初接收该属性访问请求的那个对象（即 `.` 前面的对象）。这是保证即使在原型链深处执行 getter 时，`this` 依然指向派生类实例的关键机制。

## 3. 普通对象 (Ordinary Objects) vs 异质对象 (Exotic Objects)

规范将对象分为两类：
- **普通对象**: 对于上述 13 个内部方法，使用的是引擎默认的通用算法实现。
- **异质对象**: 至少对一个内部方法进行了**自定义覆盖**的对象。

### 常见的异质对象：
1. **Array Exotic Objects (数组)**
   - 重写了 `[[DefineOwnProperty]]`。
   - 当你修改数组的 `.length` 时，它会魔术般地删除大于等于该长度的数字索引属性。当你推入新元素导致索引增加时，它会自动更新 `.length`。普通对象无法做到这一点。
2. **String Exotic Objects (字符串包装对象)**
   - 重写了 `[[GetOwnProperty]]` 和 `[[OwnPropertyKeys]]`，使其可以通过索引（如 `"hello"[1]`）访问字符。
3. **Proxy Objects (代理对象)**
   - Proxy 是终极的异质对象。它可以重写全部 13 个内部方法！这就是为什么 Proxy 能拦截几乎一切对象操作。

## 4. `[[Prototype]]` 循环防止机制

你可以动态更改对象的原型，但这带来了一个严重的风险：**原型环 (Prototype Cycle)**。
如果 A 继承 B，B 又继承 A，那么任何沿着原型链查找不存在属性的操作都将导致无限死循环。

**底层防御 (Clause 10.1.2.1 OrdinarySetPrototypeOf)**：
当引擎执行 `[[SetPrototypeOf]](V)` 时：
1. 提取当前对象 `O`。
2. 循环检查：令 `p = V` (新原型)。
3. 如果 `p` 不为 `null`：
   a. 如果 `p` 和 `O` 是同一个对象内存地址，**返回 false 并抛出 TypeError (检测到了闭环)**。
   b. 令 `p = p.[[GetPrototypeOf]]()`，继续向上溯源。

引擎在每次尝试连接新原型时，都会沿着将要连接的链条全量向上扫描一次，确保当前对象不存在于新的链条上方，这被称为 Cycle Check 算法。

## 5. 内部槽 (Internal Slots) 并不是属性

需要特别澄清：在阅读规范时，类似 `[[Prototype]]`, `[[Environment]]`, `[[PromiseState]]` 这样带双方括号的标识符，被称为 **Internal Slots (内部槽)**。

- 它们**不是**对象的普通属性。
- 它们不属于属性描述符机制管理。
- 它们不能通过反射或直接语法（如 `obj['[[Prototype]]']`）被直接访问。
- 它们是 JavaScript 引擎（如 V8 在 C++ 层面分配的内存字段）纯内部状态的抽象表达。
