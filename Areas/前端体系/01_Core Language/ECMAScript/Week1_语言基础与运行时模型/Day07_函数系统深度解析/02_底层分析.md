# 函数系统深度解析 - 底层分析

在 V8 和 ECMAScript 规范的深处，函数并非铁板一块。它是通过一系列特殊的内部槽和多态方法，支撑起 JS 多范式的运行能力。

## 1. `[[Call]]` 和 `[[Construct]]` 内部方法 (Clause 10.2)

不是所有函数都可以被正常调用，也不是所有函数都可以被 `new` 实例化。这完全取决于该函数对象是否实现了相应的底层方法。

### `[[Call]](thisArgument, argumentsList)`
任何可以使用 `fn()` 语法执行的对象，规范要求它必须实现 `[[Call]]` 内部方法。具有 `[[Call]]` 方法的对象在规范中被称为 **Callable (可调用对象)**。
- 只有普通函数、箭头函数、生成器函数、Bound Function (bind返回的函数)、Proxy拦截器等实现了它。
- Class 的 `constructor` 方法虽然是函数，但规范硬性规定：如果未使用 `new` 而直接对 Class 发起 `[[Call]]` 操作，必须抛出 TypeError。

### `[[Construct]](argumentsList, newTarget)`
任何可以使用 `new Constructor()` 语法的对象，必须实现 `[[Construct]]`。具有此方法的对象被称为 **Constructor (构造器)**。
- 普通函数、Class 实现了它。
- **箭头函数、Generator、Async 函数、大多数内置方法 (如 `Math.max`) 没有实现它。** 对它们使用 `new` 就会抛出 `TypeError: X is not a constructor`。

## 2. Non-Simple Parameter List 导致双作用域 (Clause 15.2)

ES6 引入了默认参数、剩余参数 (Rest) 和解构赋值。这三者被称为**非简单参数列表 (Non-Simple Parameter List)**。

规范中有一个极其隐蔽的设计：如果一个函数含有非简单参数，**引擎会为参数列表单独创建一个独立的作用域 (Environment Record)**，且这个作用域作为函数体内部作用域的父作用域（`outer` 链向它）。

```javascript
let x = 1;

// y 有默认值，触发了非简单参数列表双作用域机制
function foo(y = function() { x = 2; }) {
    var x = 3; 
    y(); // 执行默认函数，它试图修改其作用域链上的 x
    console.log(x); // 打印 3 (内部函数体的 var x 并未被修改)
}

foo();
console.log(x); // 打印 2 (外部全局的 x 被修改了！)
```
**底层解释**：
由于双作用域机制：
1. 创建参数作用域 `ParamEnv`，参数 `y` 的闭包绑定到了这个 `ParamEnv`，而 `ParamEnv` 的 `outer` 是全局环境。
2. 创建函数体作用域 `BodyEnv`，它的 `outer` 是 `ParamEnv`。
3. `var x = 3` 创建在 `BodyEnv` 中。
4. 调用 `y()` 时，它沿着 `ParamEnv` 向上找 `x`，直接找到了全局的 `x` 并将其改为 2。完全碰不到 `BodyEnv` 中的局部变量。

> [!WARNING]
> 这是 JS 规范设计上的严重深坑，工程中严禁在默认参数函数中依赖或修改外部变量，避免产生诡异的状态隔离！

## 3. `new.target` 元属性 (Clause 13.3.8)

`new.target` 是一种特殊的规范构造，用于在函数内部感知自己是“如何被调用的”。

在 `[[Construct]]` 的算法执行时，引擎会将触发实例化的最底层类/函数对象传递给内部状态，并暴露为 `new.target`。如果函数是通过 `[[Call]]`（普通调用）执行的，`new.target` 将为 `undefined`。

**应用：实现抽象基类 (Abstract Class)**
```javascript
class Shape {
    constructor() {
        if (new.target === Shape) {
            throw new Error("Abstract class cannot be instantiated directly.");
        }
    }
}
class Circle extends Shape {
    constructor() {
        super(); // 此时 super 内部的 new.target 指向 Circle
    }
}

new Shape(); // Error
new Circle(); // 成功
```

## 4. 箭头函数为什么没有 this 和 arguments？

规范 (Clause 15.3) 在定义箭头函数时采用了最精简的抽象操作。
- 在 `InstantiateArrowFunctionExpression` 阶段，引擎不会为它挂载 `prototype` 对象，也剥夺了它的 `[[Construct]]` 能力。
- 箭头函数没有自己的 Function Environment Record（严格来说，它使用的是普通的 Declarative Environment Record，将其 `[[ThisBindingStatus]]` 设为 `lexical`）。
- 因为是 `lexical`，当试图在箭头函数内访问 `this` 或 `arguments` 时，底层的环境解析算法 `ResolveBinding` 发现当前作用域无法提供这些绑定，只能沿着 `[[OuterEnv]]` 继续向上冒泡，直到找到最近的普通函数或全局作用域为止。

## 5. Generator 状态机底层

在 V8 底层，生成器本质上是一个编译生成的 **状态机 (State Machine)**。

规范中定义了生成器对象的 4 种内部状态：
1. **`suspendedStart`**: 初始化完毕，还未调用第一次 `next()`。
2. **`executing`**: 正在运行 `yield` 之间的代码。
3. **`suspendedYield`**: 遇到了 `yield`，挂起当前上下文，保存所有局部变量和程序计数器 (PC)，退出执行栈。
4. **`completed`**: 遇到了 `return` 或是代码跑完。

**挂起与恢复的黑魔法**：
在 C++ 层面，当遇到 `yield` 时，V8 会发生一次**上下文切换 (Context Switch)**。它不仅保存了变量值，还利用协程 (Coroutine) 的思想，将栈帧的状态打包保存到堆内存 (Heap) 中的 Generator Object 上。下次 `next()` 调用时，V8 取出这段保存的数据，直接注入寄存器并跳转 PC，就像从未中断过一样。
这是 `async/await` 能够“在同步的写法中实现异步非阻塞等待”的物理基石。
