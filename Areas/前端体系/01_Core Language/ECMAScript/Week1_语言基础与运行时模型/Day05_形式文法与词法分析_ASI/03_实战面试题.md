# 形式文法与词法分析·ASI - 实战面试题

这一节汇集了关于 ASI 与词法分析最令人抓狂的面试题目。能够全部答对，说明对 JS 引擎的解析机制有了深刻的了解。

## 1. 9个受限产生式总结表 (面试必背)

面试官问：“哪些关键字后面换行会引发致命 bug？”

| 关键字/符号 | 后面跟换行符引发的结果 | 典型错误示例 |
| :--- | :--- | :--- |
| `return` | 强制返回 `undefined` | `return \n 1;` 结果为 `undefined` |
| `throw` | 抛出 `SyntaxError: Illegal newline after throw` | `throw \n new Error();` (注意这里连执行都不会执行，直接语法错误) |
| `break` / `continue`| 跳出当前循环/语句，不会跳转到对应标签 | `break \n label;` 等同于普通 break，忽略了 label。 |
| `yield` | 返回 `undefined` | `yield \n 1;` 被拆为 `yield; 1;` |
| 箭头 `=>` 前 | `SyntaxError: Unexpected token '=>'` | `(x) \n => x` (参数和箭头不能换行) |
| 后置 `++` / `--` | 被截断，变成前一条语句的结尾，符号变成前置 | `a \n ++b` 变成 `a; ++b;` |

## 2. 经典工程陷阱解析

### 陷阱 1：无防御分号引发的立即执行函数连体

**题目**：以下代码输出什么？
```javascript
var a = function() {
    console.log("first")
}

(function() {
    console.log("second")
})()
```

**解析**：
很多初学者认为会依次打印 "first" 和 "second"。但实际上会抛出 **TypeError: a is not a function** 或者抛出无法引用的错。
为什么？因为中间没有分号。引擎解析为：
`var a = function() { ... }(function() { ... })();`
这就变成：定义完函数后，立刻把第二个函数当作参数传递给第一个函数执行。
如果第一个函数没有返回值（返回 `undefined`），那么最后的 `()` 试图去调用 `undefined`，就会抛出 `TypeError`。

### 陷阱 2：解构赋值引发的灾难

**题目**：以下代码会发生什么？
```javascript
let a = 1
let b = 2
let c = 3

[a, b] = [b, a]
console.log(a, b)
```

**解析**：
直接抛出错误。原因和陷阱1类似，解析器将其连起来读：
`let c = 3[a, b] = [b, a]`
试图访问 `3` 这个基本类型的属性（属性名为逗号表达式 `a, b` 即返回 `b` 的值 2），`3[2]` 返回 `undefined`。然后试图向 `undefined` 赋值 `[b, a]`，这在非严格模式下可能静默失败，严格模式或进一步解构时抛出错误。

### 陷阱 3：返回闭包时的意外中断

**题目**：修复以下代码，使其能正常打印 "hello"。
```javascript
function makeClosure() {
    return
    function() {
        console.log("hello")
    }
}
const fn = makeClosure();
fn(); // TypeError: fn is not a function
```

**解析**：
由于 `return` 属于受限产生式，换行后引擎强制在 `return` 后面加了分号。导致 `makeClosure` 返回了 `undefined`。后面的 `function` 变成了一个永远不会执行的孤立函数声明。
**修复**：将 `function` 移到 `return` 同一行，或者不要在 `return` 后换行。

## 3. 手写 3 个 ASI 陷阱代码挑战

在面试中，手写出那些“反直觉”的 JavaScript 语法片段是展现功底的好方法。

### 挑战 1：手写一段代码，使连续的数组连写导致属性访问

```javascript
// 代码：
const arr1 = [1, 2]
const arr2 = [3, 4]
const result = arr1
[arr2[0]] // 不小心把 [3] 当成了属性访问写在了下一行

// 引擎解析结果：
// const result = arr1[3]; 
// 所以 result 为 undefined
console.log(result); // undefined
```

### 挑战 2：利用正则表达式词法引发歧义

```javascript
// 代码：
const a = 1
const b = 2
const g = 3

const c = a
/b/g.test('b')
// 这里开发者想赋值 c = 1，然后用正则测试一下。
// 但解析器将其视为除法！

// 引擎解析结果：
// const c = a / b / g.test('b'); 
// 即 1 / 2 / false (转为0) -> Infinity
console.log(c); // Infinity
```

### 挑战 3：手写证明带标签的 break 被 ASI 截断

```javascript
// 代码：
outerLoop: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) {
            break 
            outerLoop; // 开发者想跳出外层循环
        }
        console.log(`i=${i}, j=${j}`);
    }
}
// 输出结果会打印出 i=2 的情况，因为 break outerLoop 被截断成了 break; (只跳出了内层循环)。
// outerLoop; 变成了一行无用的表达式语句。
```
