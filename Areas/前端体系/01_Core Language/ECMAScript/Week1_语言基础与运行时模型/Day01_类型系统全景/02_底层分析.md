# Day 01 · 类型系统全景 — 底层分析

> **规范视角**：从 ECMA-262 Clause 6 出发，拆解每种类型的规范定义、V8 引擎的物理内存表示、以及 `typeof null === 'object'` 这一历史性 bug 的真正成因。

---

## 一、规范中的类型系统（Clause 6）

### 1.1 ECMAScript Language Types vs Specification Types

ECMA-262 定义了两类截然不同的「类型」：

| 类型分类 | 定义 | 开发者可见？ |
|:---|:---|:---|
| **ECMAScript Language Types**（Clause 6.1）| 开发者在代码中使用的值的类型 | ✅ 是 |
| **ECMAScript Specification Types**（Clause 6.2）| 仅在规范算法描述中使用的抽象类型 | ❌ 否（引擎内部概念） |

**规范类型**（Clause 6.2）是规范用来描述语义的工具，不对应任何 JS 值：

| 规范类型 | 用途 |
|:---|:---|
| `List` | 算法中的有序列表 |
| `Record` | 命名字段的结构体（如 Property Descriptor）|
| `Completion Record` | 描述语句执行结果（normal / break / continue / return / throw）|
| `Reference Record` | 描述变量/属性访问的抽象（base + name + strict）|
| `Environment Record` | 作用域中的变量绑定集合 |
| `Abstract Closure` | 捕获变量的抽象可调用对象 |

> [!NOTE]
> **Reference Record** 是理解赋值、`delete`、`typeof` 行为的关键。当你写 `a.b.c = 1`，规范内部会创建一个 Reference Record 描述这次访问，再调用 `PutValue` 操作。

### 1.2 七种语言类型的规范定义

#### Undefined（Clause 6.1.1）
```
The Undefined type has exactly one value, called undefined.
Any variable that has not been assigned a value has the value undefined.
```
规范层面：`undefined` 是唯一值，与「未赋值」状态等同。

#### Null（Clause 6.1.2）
```
The Null type has exactly one value, called null.
```
规范层面：`null` 是刻意的「无对象值」，通常表示一个期望存放对象的变量当前为空。

#### Number（Clause 6.1.6.1）
规范采用 **IEEE 754-2019 binary64 格式**：
- 64 位：1 位符号 + 11 位指数 + 52 位尾数
- 值域：约 ±1.8 × 10^308
- 特殊值：`+0`、`-0`、`+Infinity`、`-Infinity`、`NaN`

```
规范明确说明：
+0 === -0 为 true（Abstract Equality 和 Strict Equality 都相等）
但 Object.is(+0, -0) 为 false（SameValue 算法区分 ±0）
```

#### String（Clause 6.1.4）
```
The String type is the set of all ordered sequences of zero or more
16-bit unsigned integer values ("elements").
```
- JS 字符串是 **UTF-16 码元序列**，`length` 是码元数
- 对 BMP 外字符（如 emoji、CJK 扩展区）使用代理对（Surrogate Pair）表示
- 字符串是**不可变**的（immutable）

## 二、`typeof` 的底层实现机制

### 2.1 规范算法（Clause 13.5.3）

```
typeof UnaryExpression 的求值步骤：
1. val = 对 UnaryExpression 的求值结果（Reference Record）
2. 如果 val 是 Reference Record：
   a. 如果 IsUnresolvableReference(val) 为 true → 返回 "undefined"
3. val = GetValue(val)（解包 Reference Record 获取真实值）
4. 根据 val 的类型返回字符串：
   - Undefined → "undefined"
   - Null      → "object"   ← 规范明确定义！
   - Boolean   → "boolean"
   - Number    → "number"
   - String    → "string"
   - Symbol    → "symbol"
   - BigInt    → "bigint"
   - Object（如果有 [[Call]] 内部方法）→ "function"
   - Object（否则）→ "object"
```

**`typeof null === 'object'` 不是 bug 的 bug**：
规范在 Clause 13.5.3 中明确规定了这一行为。这不是规范的遗漏，而是被规范化的历史 bug。

### 2.2 V8 引擎的 Tag 机制（物理实现）

V8 中，每个 JavaScript 值以 64 位指针或立即数表示。通过低位 Tag bits 区分类型：

```
V8 值的内存表示（简化）：

┌─────────────────────────────────┬──────────┐
│           payload (高位)         │ tag (低位)│
└─────────────────────────────────┴──────────┘

Tag 规则（V8 内部）：
- xxxx...xxx1  → Smi（Small Integer，31位有符号整数，最常见！）
- xxxx...x000  → HeapObject 指针（指向堆上分配的对象）
- 特殊标记用于 Undefined、Null、True、False 等
```

**Smi（Small Integer）优化**：
```cpp
// V8 源码概念（简化）
// 整数直接编码在指针值中，无需堆分配
// v8::internal::Smi::FromInt(42) 在 64 位系统产生 84（42 << 1 | 1）
```

**为什么 `typeof null === 'object'`（历史原因）**：

在 JavaScript 最初的 32 位实现（Brendan Eich 在网景的原始代码）中：
```
值的 32 位表示：
- 低 3 位为 tag
  000 = object（Object 引用）
  001 = int（整数）
  010 = double（浮点数，高位指向 double）
  100 = string（字符串）
  110 = boolean（布尔值）
  
null 被表示为 NULL 指针（全零），tag = 000 → object！
```

当 `typeof` 检查 null 的 tag 为 `000` 时，就返回了 `"object"`。这个 bug 随着 ES1 规范化而成为了「历史包袱」，不能修复（修复会破坏大量依赖此行为的旧代码）。

> TC39 曾提案修复此 bug（`typeof null === "null"`），但因向后兼容性问题被拒绝。

## 三、Symbol 的底层唯一性机制

### 3.1 规范定义（Clause 6.1.5）

```
Each possible Symbol value is unique and immutable.
Each Symbol value immutably holds an associated value called [[Description]]
that is either undefined or a String value.
```

Symbol 的唯一性由规范保证，每次 `Symbol()` 调用产生一个在**规范语义上独立**的值，引擎通过内部计数器或内存地址保证唯一性。

### 3.2 Well-Known Symbols（Clause 6.1.5.1）

规范定义了一组内置 Symbol，用于定制对象的内置行为：

| Symbol | 对应内置操作 | 规范引用 |
|:---|:---|:---|
| `Symbol.iterator` | `for...of`、展开运算符 | Clause 7.4 |
| `Symbol.asyncIterator` | `for await...of` | Clause 7.4 |
| `Symbol.toPrimitive` | 对象参与运算的类型转换 | Clause 7.1.1 |
| `Symbol.toStringTag` | `Object.prototype.toString` 的结果 | Clause 20.1.3 |
| `Symbol.hasInstance` | `instanceof` 运算符 | Clause 13.10.2 |
| `Symbol.species` | 派生对象的构造器选择 | 多处 |
| `Symbol.isConcatSpreadable` | `Array.prototype.concat` 的展开行为 | Clause 23.1.3 |

## 四、规范类型的工程价值：Completion Record

`Completion Record` 是规范中最重要的规范类型之一，它描述所有语句的执行结果：

```
Completion Record 结构：
{
  [[Type]]:   normal | break | continue | return | throw
  [[Value]]:  任意值（normal/return/throw 时有意义）
  [[Target]]: string | empty（break/continue 的标签目标）
}
```

**工程启示**：
```javascript
// try-catch-finally 的行为由 Completion Record 链决定
function test() {
  try {
    return 'try';       // Completion { type: return, value: 'try' }
  } finally {
    return 'finally';   // finally 的 return 覆盖 try 的 return！
  }
}
console.log(test()); // 'finally'
// 原因：finally 的 Completion Record 类型为 return，优先级高于 try 的 return
```

## 五、V8 中的值表示优化（内存布局）

### 5.1 Pointer Tagging 详解

```
64 位系统中 V8 的堆指针表示（Pointer Compression）：
┌──────────────────────────────────────────────────────────────┐
│ 在开启指针压缩（Pointer Compression）的模式下，              │
│ 堆指针只用 32 位偏移量 + 固定 cage base 地址                │
│ 节省约 40% 内存（Chrome 实测数据）                           │
└──────────────────────────────────────────────────────────────┘

值类型的表示：
1. Smi（小整数）：值直接编码在"指针"的 payload 中
   → 无堆分配，访问极快（O(1) 无间接寻址）

2. HeapNumber：双精度浮点数分配在堆上
   → 比 Smi 慢（需间接寻址）
   → V8 优化：对热路径的 HeapNumber 进行 unboxing

3. HeapObject：所有其他对象（string、object、array、function...）
   → Map（隐藏类）指针 + 对象字段
```

### 5.2 类型对性能的影响

```javascript
// 性能友好：保持变量为 Smi（整数范围内）
let counter = 0;
for (let i = 0; i < 1e6; i++) {
  counter++; // 始终是 Smi，V8 可充分优化
}

// 性能降级：从 Smi 变成 HeapNumber
let x = 0;
x = 0.5;  // V8 需要重新分配为 HeapNumber，并可能触发 IC 失效

// 性能友好：数组保持单一类型（Monomorphic Array）
const arr = [1, 2, 3];        // PACKED_SMI_ELEMENTS（最快）
arr.push(0.5);                 // 降级为 PACKED_DOUBLE_ELEMENTS
arr.push('str');               // 降级为 PACKED_ELEMENTS（最慢）
```

> [!TIP]
> 使用 `%HasSmiElements(arr)` 等 V8 内置函数（需 `--allow-natives-syntax`）可以在 Node.js 中检测数组元素类型，用于性能分析。

## 六、BigInt 的规范定义（Clause 6.1.6.2）

```
The BigInt type represents an integer value. The value may be any integer,
with no upper or lower bound.

Unlike Number, BigInt does not have a notion of NaN, Infinity, or -0.
```

BigInt 的运算全部定义为精确整数运算，规范中的 `BigInt::add`、`BigInt::multiply` 等操作都基于数学整数算术，不存在溢出或精度问题。
