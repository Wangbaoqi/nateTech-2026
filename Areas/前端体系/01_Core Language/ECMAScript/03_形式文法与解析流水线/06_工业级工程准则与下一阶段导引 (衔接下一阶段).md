## 一、 工业级工程防御准则清单（Best Practices）

基于对 ECMAScript 编译前端与形式文法的深层理解，团队在架构与编码时应确立以下军规：

### 1. 变量与作用域准则
- 🚫 **全面弃用 `var`，100% 拥抱 `const` 优先与 `let` 补位**：
  - `var` 的无序提升与函数级作用域穿透会导致变量状态不可预测；`const` 优先不仅避免了意外重赋值，更向现代 JIT 引擎传递了强烈的静态类型稳定信号。
- 🛡️ **严格遵守 TDZ 纪律，拒绝声明下置**：
  - 永远在块级作用域的第一行完成所有 `const` / `let` 的声明与初始值绑定，绝不依赖所谓“变量提升”的心智漏洞。

### 2. 语句与分号准则
- ⚠️ **坚决避开 9 大受限产生式（Restricted Productions）换行坑**：
  - `return`、`throw`、`yield`、`break`、`continue` 后面**严禁立即换行**；返回对象字面量时，起始 `{` 必须紧跟在 `return` 同一行：
    ```javascript
    // ❌ 灾难：触发 ASI 自动插入分号，返回 undefined
    return
      { status: 200 };

    // ✅ 正确规范写法
    return {
      status: 200
    };
    ```
- 🔒 **分号风格选择**：
  - 若团队采用 ESLint / Prettier 无分号风格（`semi: false`），必须在以 `(`、`[`、`/`、`+`、`-`、反引号开头的代码行首**强制前置防御性分号 `;`**，防止语法并轨崩溃。

### 3. 构建工具与打包优化准则
- ⚡ **善用 IIFE 括号提示 V8 跳过预解析（Pre-parser）**：
  - 在大型应用打包时，确保入口启动函数使用完整的圆括号包裹 `(function() { ... })()`，明确告知 V8 立即启动 Full Parser 构建 AST 与字节码，减少启动阶段因二次解析带来的白屏等待。
- 📦 **全面迁移至原生 ESM 模块体系（Module Mode）**：
  - 尽早移除全局 Script 脚本包裹模式，享受模块模式带来的默认全局严格模式、顶级 `await` 支持与更加严谨的静态导出活绑定。
