ECMAScript 源码解码与 SourceCharacter 流转换流水线 (Clause 11) ^qyW09EYk

【第一阶段：物理二进制字节流捕获】 (Raw Byte Ingestion)  [规范对照：Host Environment (文件系统 / HTTP 网络流 / stdin)]

1. 物理来源: 本地 .js 文件读取 (fs.readFile) 或网络传输 (Transfer-Encoding: chunked)
2. 内存形态: 连续的 8 位无符号整数序列 (Raw Octets / Buffer)
3. 数据特征: 纯粹的底层机器字节 (例如 EF BB BF 63 3D 22 F0 A0 AE B7 22 3B 0D 0A)
4. 状态边界: 此时在物理内存中完全没有字符、变量名或语法的概念，仅为原始字节流 ^ip7H0bbq

【第二阶段：BOM 签名探测与编码判决】 (Encoding Sniffing & Stripping)  [规范对照：Host Decoder & Web MIME Encoding Standards]

1. 前导签名探测 (BOM Sniffing):
   • 命中 0xEF, 0xBB, 0xBF -> 判定为 UTF-8 编码并自动剥离前 3 字节
   • 命中 0xFE, 0xFF -> UTF-16 BE / 命中 0xFF, 0xFE -> UTF-16 LE
2. 默认强制回退: 无 BOM 时，依据规范强制以 UTF-8 作为默认字符编码
3. 剥离防御: 剥离的 BOM 头绝对不能泄漏给后续词法分析器，必须在解码前物理切除 ^Ax5rJPVR

【第三阶段：多字节状态机解码为码点】 (Byte-to-CodePoint Decoding)  [规范对照：Unicode Standard & UTF-8 Multi-byte Decoding Algorithm]

1. 变长字节解码分流:
   • 单字节 (0xxxxxxx) -> ASCII 码点 (U+0000 ~ U+007F)
   • 双字节 (110xxxxx 10xxxxxx) -> U+0080 ~ U+07FF
   • 三字节 (1110xxxx 10xxxxxx 10xxxxxx) -> BMP 基本多语言平面 (如汉字 U+0800 ~ U+FFFF)
   • 四字节 (11110xxx 10xxxxxx 10xxxxxx 10xxxxxx) -> 辅助平面生僻字/Emoji (如 '𠮷' U+20BB7)
2. 容错回退机制: 遇到损坏的不完整字节序列时，插入 Unicode 替换字符 U+FFFD () ^kBEsOjIU

【第四阶段：特殊行终止符与 Hashbang 正规化】 (Normalization)  [规范对照：Clause 11.2 (Line Terminators) & Hashbang Grammar]

1. 换行符折叠 (CRLF Normalization): 将 Windows 风格 \r\n (0x0D 0x0A) 折叠为单一 <LF> (0x0A)
2. 四大行终止符识别: <LF> (U+000A), <CR> (U+000D), <LS> (U+2028), <PS> (U+2029)
3. 首行 Hashbang 处理: 若以 #! 开头 (如 #!/usr/bin/env node)，标记为单行解释器注释跳过
4. 源码位置网格构建: 维护字符 Offset 偏移量与物理行列号 (Line, Column) 的映射索引 ^ju7z1lQM

【第五阶段：生成规范标准 SourceCharacter 连续流】 (SourceCharacter Stream)  [规范对照：Clause 11.1 (Source Text Definition)]

1. 规范形式定义: SourceCharacter :: any Unicode code point (范围: U+0000 ~ U+10FFFF)
2. 抽象数据结构: 纯净的 Unicode 码点序列 [ U+0063, U+003D, U+0022, U+20BB7, U+0022, U+003B, U+000A ]
3. 关键分水岭心智: 在 SourceCharacter 流中，生僻字 '𠮷' 依然是单一完整的 U+20BB7 码点！
   尚未被拆分成 UTF-16 代理对 (D842 DFB7)，所有物理编码差异在此层被彻底抹平！ ^3pzizSVD

【第六阶段：无缝交付编译前端入口抽象操作】 (Handoff to Compiler)  [规范对照：Clause 11.1.5 (ParseText) & Clause 12 (Lexical Grammar)]

1. 执行抽象操作入口: ParseText(sourceText, goalSymbol) 接收纯净 SourceCharacter 流
2. 词法扫描器 (Scanner) 启动: 按照词法文法规则逐码点读取，结合语法上下文切换目标符号
